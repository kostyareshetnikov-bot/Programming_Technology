# Задание 2. Склад

## 1. Постановка задачи
Реализовать учёт товаров на складе. Хранение: словарь `артикул → {название, количество, цена}`. Операции: поступление товара, продажа, расчёт общей стоимости запасов, просмотр склада.

## 2. Входные и выходные данные
| Входные данные                                    | Выходные данные |

| Артикул, название, количество, цена (поступление) | Сообщение «добавлен» / «пополнено» / ошибка |
| Артикул, количество (продажа)                     | Сумма продажи или ошибка (нет товара, не хватает остатка) |
| Команда «стоимость»                               | Общая стоимость запасов (число) |
| Команда «показать»                                | Таблица: артикул, название, количество, цена, сумма |
| Команда «сохранить/загрузить»                     | Файл `warehouse.json` / загруженный склад |

## 3. Обоснование выбора структуры данных
Каждый товар однозначно определяется **уникальным артикулом**, и почти все операции начинаются с поиска товара по артикулу. Поэтому выбран **словарь `dict`**:
- поиск, добавление и изменение по ключу в среднем за **O(1)**;
- уникальность ключей исключает дубли артикулов.

У каждого товара несколько свойств, поэтому значение — **вложенный словарь** `{"name", "qty", "price"}`.
В `list` поиск по артикулу занял бы O(n).
Расчёт стоимости проходит по всем товарам, поэтому работает за O(n).

## 4. Алгоритм
**Поступление:**
1. Привести артикул к верхнему регистру и проверить, что он не пустой, количество > 0, а цена ≥ 0.
2. Если артикул уже есть, увеличить количество и обновить цену.
3. Если нет, проверить название и создать новую запись.

**Продажа:**
1. Если артикула нет в словаре, вывести ошибку.
2. Если количество ≤ 0 или больше остатка, вывести ошибку (склад не меняется).
3. Иначе уменьшить остаток и вернуть сумму продажи `qty * price`.

**Стоимость запасов:** сумма `qty * price` по всем товарам.

## 5. Дополнительная функция: сохранение в JSON
Склад сохраняется в `warehouse.json` и загружается обратно (`json.dump` / `json.load`, `ensure_ascii=False`, чтобы кириллица читалась). Если файла нет или он повреждён, создаётся пустой склад.
**Влияние на выбор структуры:** словарь с вложенными словарями один в один превращается в JSON-объект, поэтому дополнительные преобразования не нужны. Ключи-артикулы — строки, а это требование JSON. Это дополнительный аргумент в пользу `dict`.

## 6. Вывод
Для данных с уникальным ключом удобнее всего словарь: поиск и изменение за O(1), удобная вложенная структура, прямое сохранение в JSON. Программа обрабатывает отсутствующие ключи, нехватку товара и неверный ввод.

# Задание 3. История браузера

## 1. Постановка задачи
Смоделировать кнопки «Назад» и «Вперёд» браузера с помощью двух стеков `back` и `forward`. Операции: переход по URL, назад, вперёд. При новом переходе история «вперёд» должна очищаться.

## 2. Входные и выходные данные
| Входные данные    | Выходные данные |
|---|---|
| URL (строка)      | Новая текущая страница или отказ (пустой URL / та же страница) |
| Команда «назад»   | Предыдущая страница или «Назад идти некуда» |
| Команда «вперёд»  | Следующая страница или «Вперёд идти некуда» |
| Команда «стеки»   | Текущая страница и содержимое стеков back и forward |
| Команда «история» | Полный список посещённых страниц |

## 3. Обоснование выбора структуры данных
«Назад» всегда возвращает на **последнюю** покинутую страницу, «Вперёд» — на последнюю страницу, с которой вернулись. Это принцип **LIFO**, поэтому используются **два стека**:
- `back` — страницы, на которые можно вернуться;
- `forward` — страницы, на которые можно пойти вперёд.

Стек реализован на `list`: `append()` и `pop()` работают с концом списка за **O(1)**. `deque` не нужен, потому что работа идёт только с одним концом.
Состояние браузера хранится в словаре `{"current", "back", "forward", "history"}`, так все данные передаются в функции одним объектом.

## 4. Алгоритм
**Переход по URL:**
1. Если URL пустой или совпадает с текущим, отказать.
2. Положить текущую страницу в `back`.
3. Сделать URL текущей страницей.
4. **Очистить `forward`**: после нового перехода старая ветка «вперёд» теряет смысл.
5. Добавить URL в историю.

**Назад:**
1. Если `back` пуст, вернуть `None`.
2. Положить текущую страницу в `forward`.
3. Текущая = `back.pop()`.

**Вперёд:**
1. Если `forward` пуст, вернуть `None`.
2. Положить текущую страницу в `back`.
3. Текущая = `forward.pop()`.

## 5. Дополнительная функция: история посещений
Каждая открытая страница (переход, назад, вперёд) дописывается в список `history`, его можно вывести пунктом меню 5.
**Влияние на выбор структуры:** стеки `back`/`forward` теряют страницы при `pop()` и `clear()`, поэтому полную хронологию они не сохраняют. Для неё нужен отдельный `list`, в который только добавляют (O(1)) и который просматривают целиком.

## 6. Вывод
Навигация «Назад/Вперёд» естественно реализуется двумя стеками LIFO. Ключевой момент — очистка стека `forward` при новом переходе. Программа безопасно обрабатывает пустые стеки, пустой URL и повторный переход.

# ЛР №12 — Вариант 3 (базовый): Авторизация в системе заметок

**Условие:** приватная страница с заметками и выход из сессии.

**Как сделано:** серверная сессия. После входа сервер создаёт сессию в памяти и отдаёт браузеру только случайный идентификатор в cookie `sid` (HttpOnly, SameSite=Strict). Заметки отдаются только с живой сессией и только владельцу.

**Творческое задание:** подтверждение выхода (диалог `<dialog>`) и всплывающие уведомления об успехе и ошибках. Выход нельзя нажать случайно, а пользователь всегда видит, чем закончилось действие.

## Запуск
```bash
npm install
npm start            # http://localhost:3001, сессия живёт 15 минут
npm run start:short  # то же, но сессия живёт 30 секунд — для проверки истечения
```

Тестовые учётные записи (не реальные данные):

| Логин | Пароль |
|---|---|
| `aliya` | `Aliya#12` |
| `daniyar` | `Daniyar#12` |

В коде пароли не хранятся, только хеши scrypt (`server/db.js`). Хеш для нового пользователя: `npm run hash -- НовыйПароль`.

## Структура
```

├── css/theme.css     — общая тема (одинаковая во всех трёх проектах)

└── js/
    ├── api.js        — обёртка над fetch
    ├── ui.js         — общие функции интерфейса (одинаковые во всех проектах)
    └── app.js        — логика страницы
```

## Схема входа и выхода
```
Браузер                          Сервер
   │  POST /api/login {login, password}
   │ ──────────────────────────────▶ пустые поля?        → 400
   │                                 хеш не совпал?       → 401 «Неверный логин или пароль»
   │                                 создать сессию в памяти
   │ ◀────────────────────────────── 200 + Set-Cookie: sid=…; HttpOnly; SameSite=Strict
   │
   │  GET /api/notes  (cookie уходит сама)
   │ ──────────────────────────────▶ requireAuth: сессии нет → 401, истекла → 401 session_expired
   │ ◀────────────────────────────── 200 только свои заметки
   │  GET /api/notes/4 (чужая)       → 403
   │
   │  POST /api/logout
   │ ──────────────────────────────▶ удалить сессию на сервере, очистить cookie
   │ ◀────────────────────────────── 200 → старая cookie больше не работает
```

## API
| Метод | Адрес | Доступ | Ответы |
|---|---|---|---|
| POST | `/api/login` | все | 200, 400 (пустые поля), 401 (неверные данные) |
| POST | `/api/logout` | все | 200 |
| GET | `/api/me` | вошедший | 200, 401 |
| GET | `/api/notes` | вошедший | 200 (только свои), 401 |
| POST | `/api/notes` | вошедший | 201, 400, 401 |
| GET / DELETE | `/api/notes/:id` | владелец | 200, 401, 403 (чужая), 404 |

## Тесты

| № | Сценарий | Входные условия | Ожидаемый результат | Фактический | Статус |
|---|---|---|---|---|---|
| 1 | Корректный вход | `aliya` / верный пароль | 200, cookie `sid` HttpOnly, видны 3 заметки | Совпадает | Пройден |
| 2 | Неверный пароль | `aliya` / `wrong` | 401, «Неверный логин или пароль», cookie не выдана | Совпадает | Пройден |
| 3 | Пустые поля | логин и пароль пустые | Подсветка полей; сервер отвечает 400 с ошибками по полям | Совпадает | Пройден |
| 4 | Доступ без входа | открыть `localhost:3001/api/notes` без входа | 401 `no_session` | Совпадает | Пройден |
| 5 | Выход и повторный запрос | войти → «Выйти» → подтвердить → снова `/api/notes` (даже со старой cookie) | 401, сессия удалена на сервере | Совпадает | Пройден |
| 6 | Истекшая сессия | `npm run start:short`, войти, подождать 30 с, добавить заметку | 401 `session_expired`, экран входа с сообщением «Сессия истекла» | Совпадает | Пройден |
| 7 | Чужой ресурс | `aliya` открывает заметку №4 (она принадлежит `daniyar`) | 403 «Это чужая заметка — доступ запрещён» | Совпадает | Пройден |
| 8 | Обновление страницы | войти → F5 | Заметки остаются открытыми (`GET /api/me` → 200) | Совпадает | Пройден |

## Меры безопасности
- Пароли хранятся как хеши scrypt с солью, сравнение за постоянное время (`timingSafeEqual`).
- Одинаковый ответ на неверный логин и неверный пароль: нельзя узнать, какие логины существуют.
- Cookie `HttpOnly` (недоступна JavaScript), `SameSite=Strict` (защита от CSRF), `Secure` в продакшене (HTTPS).
- Идентификатор сессии: 256 случайных бит. При новом входе старая сессия удаляется.
- Проверка владельца на сервере (403), а не скрытие кнопок в интерфейсе.
- Данные вставляются в страницу через `textContent`, не через `innerHTML`, поэтому HTML в заметке не выполнится (XSS). Дополнительно стоит заголовок `Content-Security-Policy`.
